### Why 0% pass rate is expected

This baseline runs graders against the **current codebase state**, not against
live command execution outputs. The deterministic graders check for files that
would only exist after running `/brainstorm`, `/plan`, `/setup`, etc.:
- `test -f docs/specs/*.md` — no spec exists without running `/brainstorm`
- `test -f .harness/config.json` — no config without running `/setup`
- `grep -q 'Coverage Matrix' docs/plans/*.md` — no plan without running `/plan`

This is the correct pre-execution baseline. When Phase 2+ adds live execution
(spawning Claude Code headless), these graders will produce meaningful scores.

## Recommendations for Phase 2+

1. **Priority: Add live execution mode** — `run_baseline.py` should spawn
   `claude --no-interactive` to generate actual outputs, then run graders
   against those outputs.

2. **Convert manual cases to automated** — For behavioral cases
   (choiceexecutor, review, sync-docs), create mock-based graders that
   simulate the expected interaction without live Claude execution.

3. **Model-specific runs** — Current baseline is model-agnostic. Phase 3
   should test with `claude-sonnet-4-6` vs `claude-opus-4-5` to identify
   model-family-specific behavior.

4. **Hill-climb targets** — Once live execution is available, brainstorm
   and plan commands have the highest automated grader coverage and should
   be the first hill-climb candidates.
