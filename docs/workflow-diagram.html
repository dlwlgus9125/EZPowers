Project Harness Initialization
▾

수행 작업

  • 프로젝트 증거 수집 (repo root, manifests, source dirs, AGENTS.md, CLAUDE.md, CONTEXT.md)
  • reference docs 읽기 (setup-contract.md, domain-language.md, verification-contract.md)
  • 설정 질문 (한 번에 하나씩) — 추론 가능하면 자동 결정
  • 기존 harness 존재 시 보존/병합 확인
  • Wiring 설정 (UI 감지 시 wiring.enabled 자동 설정)
  • 필수 파일 생성: .harness/config.json, phases/index.json, docs/ slots
  • 선택적: --enable-traces 시 hooks 활성화

입력 / 출력

  • INPUT 대상 프로젝트 구조, 사용자 설정값
  • OUTPUT .harness/config.json (smoke, eval, trace 설정)
  • OUTPUT phases/index.json (setup: complete)
  • OUTPUT docs/ 슬롯 (product, reference, decisions, ux)
  • OUTPUT CONTEXT.md (프로젝트 도메인 언어)

게이트 조건

  • GATE 기존 harness 덮어쓰기 거부 시 STOP
  • GATE 필수 설정값 미제공 시 STOP
  • GATE 모든 필수 파일 존재해야 complete 마킹

/brainstorm
Interactive Design → Spec Document
▾

수행 작업

  • Phase A: Architecture Baseline — ASR Ledger, Option Matrix, Lifecycle, Quality Budgets, Decision Log 수집
  • AGENT Architecture Reviewer 호출 → 구조 준비 상태 검증
  • SKILL grill-with-docs 호출 → 가정 스트레스 테스트, CONTEXT.md 업데이트
  • Phase B: Requirement Extraction — 하나씩 질문하며 요구사항 도출
  • 각 Requirement: Input, ASR, Behavior, Output, Impact Scope, AC (Given/When/Then), Edge Cases
  • Wiring Map 생성 (실행 가능 아티팩트인 경우)
  • Phase C: Spec Assembly — docs/specs/ 에 문서 생성
  • AGENT Spec Reviewer 호출 → 완전성/일관성 검증

입력 / 출력

  • INPUT .harness/config.json, CONTEXT.md, 사용자 아이디어/요구
  • OUTPUT docs/specs/{feature}-spec.md (Spec Document)
  • OUTPUT CONTEXT.md 업데이트 (도메인 용어 선명화)
  • OUTPUT docs/decisions/ADR-*.md (필요 시)

게이트 조건

  • GATE Architecture Reviewer PASS 필수 (Phase A 후)
  • GATE Spec Reviewer PASS 필수 (Phase C 후)
  • GATE 금지 표현 스캔 (적절히, appropriately, 필요한 경우 등)
  • GATE Negative AC 커버리지 (positive 3+ 시 negative 1+ 필수)
  • GATE Verify command shell 구문 유효성

리뷰어 상세

  • Architecture Reviewer ASR Ledger 품질, R-to-ASR 매핑, Option Matrix, Lifecycle, Quality Budgets, ADR trigger 검증
  • Spec Reviewer 6개 아키텍처 섹션, Wiring Map, 요구사항 구조, 금지 표현, Impact scope, Given/When/Then, Verify-type 검증

/pipeline-audit
Cross-Stage Completeness Gate (Spec → Plan)
▾

수행 작업 (6 Dimensions)

  • D1: Document Traceability — R이 Spec에 있고, ASR이 Ledger에 연결되는지
  • D2: Spec Depth — AC 구조(Given/When/Then), Verify command, Impact scope 존재
  • D3: Architecture Readiness — 6개 필수 아키텍처 섹션 존재 여부
  • D4: Execution Readiness — Spec이 Plan으로 분해 가능한 상태인지
  • D5: Reference Alignment — 기존 architecture.md, conventions.md 와 충돌 없는지
  • D6: Codebase Evidence — Impact scope가 실제 코드베이스와 일치하는지

입력 / 출력

  • INPUT docs/specs/*.md, docs/reference/*.md, .harness/config.json
  • OUTPUT phases/index.json audit 필드 업데이트
  • OUTPUT 라우팅 권고: READY_FOR_PLAN | NEEDS_SPEC_FIX | NEEDS_ARCH_FIX

게이트 조건

  • GATE 6개 dimension 중 하나라도 FAIL 시 진행 차단
  • GATE NEEDS_SPEC_FIX → /brainstorm 으로 회귀
  • GATE NEEDS_ARCH_FIX → 아키텍처 섹션 보강 필요

/plan
Spec → Task Decomposition + Agent Assignment
▾

수행 작업

  • Spec 읽기 → 요구사항별 Task 분해
  • Coverage Matrix 생성: 모든 R → 최소 1개 T 매핑, ASR 캐리포워드
  • Task별 구조: 완료 기준 (R번호 태깅), Verify 메서드, Impact scope, TDD Slice Contract
  • Integration Contract Matrix (2+ executable task): WM-C, WM-REG 전체 매핑
  • Full-Feature Wiring Gate 정의 (multi-task/multi-layer 작업 시)
  • Skeleton Task (새 프로젝트/실행파일): Task 1 = {skeleton}, WM-EP 참조
  • Structural Invariants 테이블: 검증 명령어 포함
  • AGENT Plan Reviewer 호출 → 실행 가능성 검증

입력 / 출력

  • INPUT docs/specs/{feature}-spec.md, .harness/config.json, CONTEXT.md
  • OUTPUT docs/plans/{feature}-plan.md (Plan Document)
  • OUTPUT Coverage Matrix (R → T 매핑)
  • OUTPUT Integration Contract Matrix (executable 시)
  • OUTPUT Full-Feature Wiring Gate 정의

게이트 조건

  • GATE Plan Reviewer PASS 필수
  • GATE 모든 R이 Coverage Matrix에 포함
  • GATE 모든 ASR이 최소 1개 Task 또는 Structural Invariants에 존재
  • GATE 2+ executable task 시 ICM 필수
  • GATE Verify 단계 없는 task = FAIL

Plan Reviewer 검증 항목

  • Coverage Matrix 완전성, ASR carry-forward
  • Task 완료 기준 R번호 태깅, Verify 메서드 구체성
  • Impact scope 교차검증, Reference breakage 체크
  • TDD Slice Contract density (behavior-bearing tasks)
  • Build config 교차 검증, View wiring verification

4
/choiceexecutor
Execution Path Selection & Orchestration
▾

실행 경로 선택 (3 Paths)

  • Path 1: Subagent — implementer-prompt.md 템플릿으로 구현 에이전트 생성, task별 독립 실행
  • Path 2: Harness (/executeharness) — EasyPowersHarness 기반 phase 변환 + 단계별 실행
  • Path 3: Inline — 현재 세션에서 직접 구현 (단순 작업용)

수행 작업 (공통)

  • Plan 읽기 → Task 순서 결정
  • Task별 실행: 코드 구현 + Verify command 실행
  • SAST 매 Task마다 정적 보안 분석 (changed files only)
  • Incremental Runnability: skeleton 이후 매 task마다 smoke.command 실행
  • Incremental Wiring Probe: 모듈 생성/수정 시 import-chain/runtime-load 검증
  • AGENT Code Reviewer 호출 (최종 구현 후)
  • AGENT Wiring Reviewer 호출 (Full-Feature Wiring Gate)
  • SKILL /sync-docs 자동 호출 (완료 후)

Path 2: /executeharness 상세

  • Preflight: harness-doctor.ps1 실행, config 검증, start hash 캡처
  • Plan → Phase 변환: harness-convert.ps1 (Task 1 → step0.md ...)
  • Step별 실행: harness-run.ps1 (timeout + logging)
  • 단계별 Runtime Smoke 검증
  • Wiring Gate 실행: harness-gate.ps1 → Wiring Reviewer dispatch
  • phases/index.json 보호 (backup & restore)

입력 / 출력

  • INPUT docs/plans/{feature}-plan.md, .harness/config.json
  • OUTPUT 구현된 코드 (프로젝트 소스)
  • OUTPUT 테스트 코드 + 검증 결과
  • OUTPUT phases/index.json 상태 업데이트
  • OUTPUT 업데이트된 reference docs (via /sync-docs)

게이트 조건

  • GATE Code Reviewer: PASS 또는 PASS_WITH_ISSUES (1회 수정 허용)
  • GATE Wiring Reviewer: PASS 필수 (TEST_GAP/CODE_GAP/SPEC_GAP = 수정 필요)
  • GATE 3회 연속 동일 이슈 → 아키텍처 재검토
  • GATE Runtime Smoke 실패 시 진행 차단
  • GATE 리뷰 루프 최대: spec/arch/plan 5회, code 10회

Code Reviewer 검증 항목

  • Plan 정합성, 코드 품질 (에러 처리, 타입 안전성, 네이밍)
  • Observability (구조적 로깅, 메트릭, trace 상관)
  • Spec Evidence Table: 각 R → 구현 파일:라인 매핑 (VERIFIED/MISSING)
  • Structural Invariants 실행, ASR Evidence 확인
  • 패키지 검증: import 정당성, lockfile, 모듈 시스템 호환

Wiring Reviewer 검증 항목

  • Route/CLI/DI 등록, import/export 경로, 이벤트 구독
  • UI 바인딩, startup hookup, entry-point 도달 가능성
  • PASS / TEST_GAP / CODE_GAP / SPEC_GAP 분류

Utility Commands

/set-rules
코딩 규칙 설계 → conventions.md 생성. /setup 후, /brainstorm 후, /plan 후 각각 호출 가능. ~20 rules 예산.
/review
변경사항 리뷰: Spec AC 대비 구현 완전성, 아키텍처 준수, 테스트, 보안, 빌드 검증. 커밋/PR 전 독립 사용.
/sync-docs
reference docs를 코드베이스 실제 상태와 동기화. /choiceexecutor 완료 후 자동 호출, 독립 사용 가능.
/eval
eval suite 실행. 4개 split (optimization, holdout, golden, honeypot). 회귀 감지, baseline 기록.
/feedback
세션 trace에 +1/-1 점수 부여. 실패 시 promote_trace.py로 eval case 변환 안내.

Skills

diagnose
6-Phase 진단 루프. Feedback Loop → Reproduce → Hypothesize → Instrument → Fix → Post-Mortem. 3회 실패 시 아키텍처 재검토.
verifyself
CoVe 자기 검증. 6차원: 탐색 깊이, 영향 범위, 대안 고려, 시간 관점, 컨텍스트 정합, 증거 충분성.
grill-with-docs
설계 스트레스 테스트. 모호한 용어 구체화, 숨은 가정 노출, 엣지케이스 도전. CONTEXT.md + ADR 즉시 업데이트.
handoff
세션 핸드오프 문서 생성. 워크플로우 상태, 컨텍스트, 미결 질문, 다음 세션 권장 스킬 기록.
zoom-out
추상화 한 단계 상승. 모듈 맵 제공, 코드 구조 조감도.
caveman
토큰 절약 모드. 출력 ~75% 압축, 기술 정확성 유지.

Eval Gate (Pre-commit)

Harness docs: check-harness-docs.ps1
Skills/commands: validate.py

차단 조건:
• Diff > 3 lines per Better-Harness rule
• evals/ 동시 수정
• Golden invariant 실패
• Optimization 평균 회귀
• Holdout >5% 하락
• 금지 표현 포함
Reviewer Agents
Spec Reviewer
Spec 문서 완전성/일관성 검증. 아키텍처 섹션, Wiring Map, 금지 표현, AC 구조, Verify-type 검증.
Verdict: PASS | FAIL
Architecture Reviewer
아키텍처 준비 상태 검증. ASR Ledger, Option Matrix, Lifecycle, Quality Budgets, ADR trigger, 참조 정합.
Verdict: PASS | FAIL
Plan Reviewer
Plan 실행 가능성 검증. Coverage Matrix, Task 분해, Verify 메서드, ICM, Wiring Gate, Skeleton task.
Verdict: PASS | FAIL
Code Reviewer
구현 코드 검증. Plan 정합, 코드 품질, Observability, Spec Evidence Table, Structural Invariants, ASR.
Verdict: PASS | PASS_WITH_ISSUES | FAIL
Wiring Reviewer
전체 기능 연결 검증. Route/DI 등록, import 경로, 이벤트 구독, UI 바인딩, entry-point 도달.
Verdict: PASS | TEST_GAP | CODE_GAP | SPEC_GAP
Workflow Runner
EZPowers 명령 프로시저 실행 (스코프 제한). /pipeline-audit, /sync-docs만 실행 가능.
Status: DONE | NO_CHANGES | NEEDS_USER | FAIL
Eval Diagnostician
실패한 eval trace 분석 → 1줄 변경 제안. 진단/내부 전용이며 user-facing 커맨드에서는 호출되지 않음.
Output: 1-line change proposal
Verification Contract (Task-Level)
SAST Gate
매 task 실행 시 변경 파일에 대한 정적 보안 분석. AC 검증 전에 실행.
Mandatory per-task
Runtime Probe
실행 가능 아티팩트의 시작 + 생존 증명. Feature 검증과 별도.
Process start + survive
Incremental Wiring
모듈 생성/수정마다 import-chain, runtime-load, e2e-touch 중 하나 검증.
Per-task probe
Smoke Command
Skeleton task 이후 매 task마다 smoke.command 실행. Incremental Runnability 보장.
After every task
Verify Command
각 AC의 Verify command 실행. 타입별 timeout: pure(10s), cli(30s), lib(30s), api(60s), e2e(120s).
Per AC execution
